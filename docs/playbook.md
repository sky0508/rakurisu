## 0. 設計原則 — 役割分担（誰が何を出すか）

精度と "入力に迷わせないUX" の両立点は、ここの線引きにある。

- **人間（対話ユーザー）が出す**: 商材の**独自便益** → それを**必要とする職種/部署** → その部署が中心の**業種** → 到達可否の**規模感**
- **AI が自動導出する（ユーザーに選ばせない）**: その部署/業種を観測する**シグナル軸**（求人 / 組織 / 業種DB 等）と**公開ソース種類**、そして実クロール

→ 対話は「便益 → 部署 → 業種 → 規模」の翻訳に集中する。
**「どのシグナルで拾うか」はユーザーに聞かない**（＝Sora も実務では AI に丸投げしている部分）。
参照: [[feedback_two_meta_axes_brainstorm]]（ドメイン方法論 と AIへの任せ方 は別軸）。

## 1. Layer 1 — 思考プロセス（対話AIの実行手順）

ふわっとした与件を渡された時に回す手順。各ステップで AI は**断定せず叩き台を先出し
→ ユーザーが Yes/No・修正**する（提案型）。ユーザーが「分からない/お任せ」なら AI が
具体候補を 2〜3 個、理由付きで出して選ばせる。

1. **商材の独自便益を1つ掴む**（ペインより先）
   - 隠れルール: 「この商材は何を上げる / 解決するか」を一言に。**全部訴求しない**。
   - 例（UACJ）: 研修の本質 = 「クリエイティビティを上げる」
2. **便益 → "ニーズがありそうな業界/セグメント" を先出し**（← 最初に表に出すのはここ）
   - 隠れルール: **最初の提案は業界/セグメント単位**（顧客が想像しやすい）。「こういうところに
     ニーズがあるのでは？」の提案型で 2〜3 個出す。部署/職種は抽象なので最初に聞かない。
   - 例: 接遇改善研修 → 「美容クリニック・病院・ホテル・小売あたりにニーズがありそう」
   - 内部推論は 便益 →（必要な職種/部署）→ 業界 の順で導いてよい。ただし**表に出すのは業界/
     セグメント**。部署の話はステップ4（絞り込み/到達）で使う。
   - 業界が非自明な商材（例: クリエイティビティ研修）は、便益が要る職種を経由して
     「プロダクト企画型メーカー（家電など）にニーズがありそう」と**業界の言葉で**先出しする。
3. **相手の反応で分岐**
   - 【ある/選んだ】→ そのセグメントを具体化。
   - 【ない/お任せ】→ 具体セグメント候補を 2〜3 個、「なぜニーズがあるか」を一言添えて選ばせる。
4. **セグメントが定まったら 規模・到達で絞る**（→ Layer 2 の普遍ルール）＋必要なら部署でsharpen
   - 例: まず従業員1,000人以下。大手も狙うなら "バイネーム/部署" を収集項目に足す前提で提案。
5. **母集団が広ければサブセグメントに割り、approach を出し分けて並列**
   - 例: 「メーカー」は広い → プロダクト別にアプローチを用意して並列検証
6. **部署/業種が定まったら、シグナルとソース種類を AI が自動で添える**（相手に選ばせない）
   - 例: 「その業界は〈業種団体名簿〉、その部署は〈◯◯職の求人〉で外から観測できます」
7. **小ロットの反応（取得率）で勝ち筋を選ぶ / 別仮説へ乗り換え**

## 2. Layer 2 — 経験パラメータ（追記式・叩けば増える）

Layer 1 の各所に差し込む実測値。網羅は狙わない。埋まった範囲で先出しに使う。

### 2.1 普遍ルール（到達 = 受付突破 / 決裁者接続）

- **従業員1,000人以下 → 到達しやすい**。代表TEL で足りることが多い。
- **大手 / 従業員多い → 部署番号・部署名・バイネームが無いと到達困難** →
  リストに担当者名/部署を積む必要（＝収集項目に反映）。
- **商材が有名ブランド絡み**（例: ANA の研修）→ 受付が担当に繋いでくれやすい。
  ※ ターゲット選定への効きは〈不確実〉タグ（商材側の属性であって target 属性か不明）。

### 2.2 セグメント別テーブル（到達中心。刺さり列は今後埋める）

| セグメント | 到達 | 必要収集項目 | メモ |
|---|---|---|---|
| 病院 | ◎ | 代表TELでOK | ANA の研修が通った |
| 美容クリニック | △（受付突破難） | 未確定 | 難しいがアプローチ価値あり |

## 3. ガードレール（仮説が雑にならない3制約）

1. **観測可能性**: 「困ってそう」で止めない。外から観測できる特徴まで落ちない仮説は却下・作り直し。
2. **ソース種類の明示必須**: 各シグナルは必ずソース種類を伴う（AI が導出）。名指せない = リスト化不可 = 無効。
3. **母集団爆発チェック**: 業種横断シグナル（求人等）は数万社に膨張 → 規模/業種で絞り軸を問い返す。

（実在サイト名・URL は断定しない。実ソース発見は後段 worker の Brave が担当。
参照: [[reference_llm_url_grounding]]）
