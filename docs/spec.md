# ラクリス spec（何を・なぜ）

## これは何か

lead-harvest（B2B リード収集）の**ジョブを実行・監視・納品確認する webapp**。
現状は営業リスト作成が「メインの Claude セッション + Python スクリプト + Sheets」に散っている。ラクリスはその実行状況と成果物を 1 画面に集約する。

現段階の成果物は**単一 HTML のデザインモック**（`index.html`）。実装前の見た目合意 + 社内共有が目的。

## なぜ

- 実行中ジョブ・GO 待ち・完了の状態が可視化されておらず、進捗が Sora の頭の中にしかない
- 納品物（Sheets / CSV）と品質バー達成状況が案件ごとにバラバラ
- 「AIっぽくない業務 UI」の社内標準を示す実例としても機能させたい

## スコープ（モック段階）

主要ビュー = ジョブ 1 本の**状態別詳細**。以下 4 state をモックに含む:

| state | 支配情報 | 主なパネル |
|---|---|---|
| done（完了） | 電話取得率 % | サマリー / パイプライン / 品質バー・Tier / 出力リンク / プレビュー表 |
| running（実行中） | Stage 進捗 % | サマリー / パイプライン(進行中) / 直近イベントログ |
| dryrun（試走 GO 待ち） | 試走 電話取得率 % | GO 判断 note / 試走メトリクス / 試走パイプライン |
| decompose（与件分解） | 仮説 3 案 | 分解 note / 仮説カード ×3 |

左レール = ジョブキュー（状態タグ付き）。ヘッダ = 新規ジョブモーダル（与件 → 用途 → 自動カラム提案）。

## 非スコープ（今はやらない）

- 実データ連携（DB / Sheets API）。モックはサンプル数値・実在しない社名
- 認証・マルチユーザー
- Next.js 実装（合意後に別フェーズ）

## デザイン方針

`docs/DESIGN.md` が正。要点: quiet-product パターン（白い主役面 + 暖チャコール脇役面 / 色はデータにだけ / CTA 1 点 / ドラマなし）。
`/rich-webapp-design` スキルの最低ラインに準拠。
